The core concept for this tinker activity was learning how to leverage AI tools to translate vague design requests into clear system components. Learning how to design system architecture was the main focus and I would also say is probably where students will struggle the most with this assignment. Since students are tasked with defining 4 main classes based off the given project description, they may question whether they are deviding behavior among the classes correctly. As a result, they might define classes whose functions overlap too much, are missing behavior or belong to another class. Since there is a lot of drafting and planning in this assignment, AI does well when you provide it with the specific point we are at in this process, this includes attaching the correct file and asking targeted questions. It also does a good job creating tests and suggesting edits to exisiting testing. AI is likely to be misleading when first designing the different components. To guide the student, I would ask them to carefully consider whether they fell like the classes they have defined and UML fully fits the initial specs.
